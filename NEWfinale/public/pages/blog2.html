Core Web Vitals: A Technical Guide for Developers

February 28, 2025
Michael Thompson
Development, SEO

Learn how to optimize your website's Core Web Vitals to improve search rankings and provide a better user experience. This technical guide breaks down LCP, FID, and CLS with practical code examples that you can implement today.

Introduction to Core Web Vitals

Core Web Vitals are a set of specific factors that Google considers important for a webpage's overall user experience. As of May 2021, these metrics have become official ranking factors, making them crucial not only for user experience but also for search visibility.

The three Core Web Vitals metrics focus on different aspects of the user experience:

  • Largest Contentful Paint (LCP): Measures loading performance
  • First Input Delay (FID): Measures interactivity
  • Cumulative Layout Shift (CLS): Measures visual stability

In this technical guide, we'll break down each metric, explain how they're measured, and provide actionable code examples to help you optimize your website. We're focusing on practical implementation rather than theory, so you can start making improvements immediately.

"Good page experience doesn't override having great, relevant content. However, in cases where there are multiple pages with similar content, page experience becomes much more important for visibility in Search."
— Google Search Central

Largest Contentful Paint (LCP)

LCP measures the time it takes for the largest content element visible in the viewport to be rendered on the screen. This is typically an image, video, or large text block that forms the main content of the page.

What's a Good LCP Score?

Good
≤ 2.5 seconds
Needs Improvement
2.5 - 4.0 seconds
Poor
> 4.0 seconds

Common Causes of Poor LCP

  • Slow server response times
  • Render-blocking JavaScript and CSS
  • Slow resource load times (especially images)
  • Client-side rendering without optimization

Optimization Techniques

1. Optimize Server Response Time

The Time to First Byte (TTFB) is a significant factor in LCP. Here are some ways to improve it:

Server Optimization - Nginx Example 
# Enable compression in nginx.conf
gzip on;
gzip_comp_level 5;
gzip_min_length 256;
gzip_proxied any;
gzip_vary on;
gzip_types
  application/javascript
  application/json
  application/x-javascript
  text/css
  text/javascript
  text/plain;

# Enable caching
location ~* \.(jpg|jpeg|png|gif|ico|css|js)$ {
    expires 30d;
    add_header Cache-Control "public, no-transform";
}

2. Eliminate Render-Blocking Resources

Defer non-critical JavaScript and CSS to prevent blocking the main thread during initial render:

HTML - Defer JS Loading 
<!-- Before: Render blocking -->
<script src="app.js"></script>

<!-- After: Deferred loading -->
<script src="app.js" defer></script>

<!-- For critical CSS: Inline it -->
<style>
  /* Critical CSS for above-the-fold content */
  .header, .hero { /* styles */ }
</style>

<!-- For non-critical CSS: Load asynchronously -->
<link rel="preload" href="styles.css" as="style" onload="this.onload=null;this.rel='stylesheet'">
<noscript><link rel="stylesheet" href="styles.css"></noscript>

3. Optimize and Prioritize LCP Element

If your LCP element is an image, optimize it and use modern image formats:

HTML - Responsive Images with WebP 
<picture>
  <source srcset="image.webp" type="image/webp">
  <source srcset="image.jpg" type="image/jpeg">
  <img src="image.jpg" alt="Description" width="800" height="600" loading="eager">
</picture>

For critical images, use preload:

HTML - Preload Critical Images 
<link rel="preload" as="image" href="hero-image.webp" type="image/webp">

Pro Tip

Always specify width and height attributes on your images to reduce layout shifts during loading. Modern browsers will respect the aspect ratio even if the image is styled to a different size with CSS.

First Input Delay (FID)

FID measures the time from when a user first interacts with your page (i.e., clicks a link, taps on a button) to the time when the browser is able to respond to that interaction. It quantifies the experience users feel when trying to interact with unresponsive pages.

What's a Good FID Score?

Good
≤ 100 ms
Needs Improvement
100 - 300 ms
Poor
> 300 ms

Common Causes of Poor FID

  • Heavy JavaScript execution
  • Long tasks that block the main thread
  • High JavaScript parsing and compilation time
  • Render-blocking resources

Optimization Techniques

1. Break Up Long Tasks

Split long JavaScript tasks into smaller, asynchronous tasks:

JavaScript - Break Up Long Tasks 
// Before: Long-running synchronous code
function processData(data) {
  // Heavy operation that takes 500ms+
  const result = heavyCalculation(data);
  updateUI(result);
}

// After: Split into smaller tasks with requestIdleCallback
function processData(data) {
  // Break the work into chunks
  const chunks = splitIntoChunks(data, 50);
  
  chunks.forEach((chunk, index) => {
    // Use requestIdleCallback to schedule work during idle periods
    window.requestIdleCallback(() => {
      const result = processChunk(chunk);
      updateUIProgressively(result, index, chunks.length);
    }, { timeout: 1000 });
  });
}

2. Optimize JavaScript Execution

Use web workers for CPU-intensive tasks:

JavaScript - Web Worker Example 
// main.js
const worker = new Worker('worker.js');
worker.postMessage({ data: complexData });
worker.onmessage = function(e) {
  const result = e.data;
  updateUI(result);
};

// worker.js
self.onmessage = function(e) {
  const result = heavyCalculation(e.data.data);
  self.postMessage(result);
};

3. Implement Code-Splitting

For frameworks like React, use dynamic imports and React.lazy for code-splitting:

JavaScript - React Code-Splitting 
// Before
import HeavyComponent from './HeavyComponent';

// After
import React, { Suspense, lazy } from 'react';
const HeavyComponent = lazy(() => import('./HeavyComponent'));

function MyComponent() {
  return (
    <Suspense fallback={<div>Loading...</div>}>
      <HeavyComponent />
    </Suspense>
  );
}

Pro Tip

Use the setTimeout() function to yield to the main thread during data processing or initialization code. This allows the browser to handle user interactions even while loading.

Cumulative Layout Shift (CLS)

CLS measures the total of all unexpected layout shifts that occur during the entire lifespan of the page. It quantifies how much visible content shifts around and helps identify unstable pages.

What's a Good CLS Score?

Good
≤ 0.1
Needs Improvement
0.1 - 0.25
Poor
> 0.25

Common Causes of Poor CLS

  • Images without dimensions
  • Ads, embeds, and iframes without dimensions
  • Dynamically injected content
  • Web fonts causing FOIT/FOUT (Flash of Invisible/Unstyled Text)
  • Actions waiting for a network response before updating the DOM

Optimization Techniques

1. Always Include Size Attributes for Media

Always specify width and height for images, videos, and other media:

HTML - Properly Sized Images 
<!-- Before: No dimensions -->
<img src="image.jpg" alt="Description">

<!-- After: With dimensions -->
<img src="image.jpg" alt="Description" width="800" height="600">

/* CSS to maintain aspect ratio while making image responsive */
img {
  max-width: 100%;
  height: auto;
}

2. Reserve Space for Ads and Embeds

Pre-allocate space for ads and embeds that load dynamically:

HTML/CSS - Ad Container 
<!-- HTML -->
<div class="ad-container">
  <!-- Ad will be injected here -->
</div>

/* CSS */
.ad-container {
  display: block;
  width: 100%;
  height: 250px; /* Fixed height based on expected ad size */
  background-color: #f1f1f1; /* Optional placeholder color */
  overflow: hidden; /* Prevents content from spilling out */
}

3. Optimize Web Font Loading

Use font-display: swap and preload critical fonts:

CSS/HTML - Font Optimization 
/* CSS */
@font-face {
  font-family: 'MyWebFont';
  src: url('webfont.woff2') format('woff2');
  font-weight: 400;
  font-style: normal;
  font-display: swap; /* Prevents invisible text while font loads */
}

/* HTML - Preload critical fonts */
<link rel="preload" href="webfont.woff2" as="font" type="font/woff2" crossorigin>

/* Optional: Reduce layout shift with font matching */
body {
  font-family: system-ui, -apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, 'MyWebFont', sans-serif;
}

4. Avoid Injecting Content Above Existing Content

For dynamically added content, use placeholders or add it at the bottom of the page:

JavaScript - Safe DOM Updates 
// Before: Inserting at the top causes layout shift
document.body.insertBefore(newElement, document.body.firstChild);

// After: Use a placeholder with the right dimensions
const placeholder = document.getElementById('notification-placeholder');
placeholder.appendChild(newElement);

// Alternative: Add new content at the end
document.body.appendChild(newElement);

Pro Tip

For content that must appear based on user interaction (like a modal or notice), consider using CSS transforms instead of properties that trigger layout changes. Transforms are handled by the compositor thread, not the main thread.

Measuring & Monitoring Core Web Vitals

Before you can optimize, you need to measure your current performance. Here are several ways to measure and monitor Core Web Vitals:

Field Tools (Real User Monitoring)

  • Chrome User Experience Report (CrUX) - Real-world data from opted-in Chrome users
  • Google Search Console - Core Web Vitals report based on CrUX data
  • PageSpeed Insights - Combines field data from CrUX with lab data from Lighthouse
  • Web Vitals JavaScript library - For custom RUM implementations

Lab Tools (Controlled Environment Testing)

  • Lighthouse - In Chrome DevTools or as a CI/CD integration
  • WebPageTest - Detailed performance analysis
  • Chrome DevTools Performance panel - In-depth performance profiling

Implementing the Web Vitals Library

For custom monitoring, you can use the web-vitals JavaScript library:

JavaScript - Web Vitals Library Implementation 
// Install via npm
// npm install web-vitals

// Or use the CDN version
import {getCLS, getFID, getLCP} from 'https://unpkg.com/web-vitals?module';

function sendToAnalytics({name, delta, id}) {
  // Send metrics to your analytics system
  // Example: Google Analytics
  ga('send', 'event', {
    eventCategory: 'Web Vitals',
    eventAction: name,
    eventLabel: id,
    eventValue: Math.round(delta),
    nonInteraction: true,
  });
}

// Measure and report each metric
getCLS(sendToAnalytics);
getFID(sendToAnalytics);
getLCP(sendToAnalytics);

Important

Field data (real user experiences) should be your primary focus when optimizing Core Web Vitals, as lab data may not accurately represent real-world conditions like device capabilities, network variability, and user interactions.

Practical Implementation Example

Let's put it all together with a real-world example. Here's how you might optimize a typical product page:

HTML/CSS/JS - Optimized Product Page 
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Product Name - Your Store</title>
  
  <!-- Preload critical assets -->
  <link rel="preload" href="critical.css" as="style">
  <link rel="preload" href="hero-product.webp" as="image" type="image/webp">
  <link rel="preload" href="fonts/brand-font.woff2" as="font" type="font/woff2" crossorigin>
  
  <!-- Inline critical CSS -->
  <style>
    /* Critical CSS that styles above-the-fold content */
    body { font-family: system-ui, sans-serif; margin: 0; }
    .hero { height: 50vh; display: flex; align-items: center; }
    .product-image { aspect-ratio: 3/2; width: 100%; height: auto; }
    /* More critical styles... */
  </style>
  
  <!-- Defer non-critical CSS -->
  <link rel="stylesheet" href="main.css" media="print" onload="this.media='all'">
  
  <!-- Preconnect to required origins -->
  <link rel="preconnect" href="https://api.yourstore.com">
</head>
<body>
  <header>
    <!-- Header content with minimal JS dependencies -->
  </header>
  
  <main>
    <section class="hero">
      <div class="container">
        <!-- Hero product image with dimensions -->
        <picture>
          <source srcset="hero-product.webp" type="image/webp">
          <source srcset="hero-product.jpg" type="image/jpeg">
          <img 
            src="hero-product.jpg" 
            alt="Product Name" 
            width="1200" 
            height="800"
            class="product-image"
            fetchpriority="high">
        </picture>
        
        <!-- Product details -->
        <div class="product-details">
          <h1>Product Name</h1>
          <p class="price">$99.99</p>
          <!-- More content -->
        </div>
      </div>
    </section>
    
    <!-- Reserve space for dynamic content -->
    <div class="reviews-container" style="min-height: 200px;">
      <!-- Reviews will be loaded here -->
    </div>
  </main>
  
  <footer>
    <!-- Footer content -->
  </footer>
  
  <!-- Defer non-critical JavaScript -->
  <script src="main.js" defer></script>
  
  <!-- Load reviews after critical content -->
  <script>
    // Wait until main thread is idle
    window.addEventListener('load', () => {
      window.requestIdleCallback(() => {
        fetchReviews().then(reviews => {
          const container = document.querySelector('.reviews-container');
          renderReviews(reviews, container);
        });
      }, { timeout: 2000 });
    });
    
    // Use Intersection Observer for lazy-loading content
    const observer = new IntersectionObserver((entries) => {
      entries.forEach(entry => {
        if (entry.isIntersecting) {
          const lazyImage = entry.target;
          lazyImage.src = lazyImage.dataset.src;
          observer.unobserve(lazyImage);
        }
      });
    });
    
    document.querySelectorAll('img[data-src]').forEach(img => {
      observer.observe(img);
    });
  </script>
</body>
</html>

This implementation demonstrates multiple optimization techniques:

  • Preloading critical resources
  • Inlining critical CSS
  • Deferring non-critical CSS and JS
  • Reserving space for dynamic content
  • Using proper image dimensions and modern formats
  • Setting fetchpriority for critical images
  • Loading non-critical content during idle periods
  • Implementing lazy loading with Intersection Observer

Conclusion

Core Web Vitals are not just important for SEO but also represent a significant shift in how we should think about web performance—focusing on the actual user experience rather than arbitrary technical metrics.

The key to successful optimization is understanding that these metrics are interconnected. Improvements in one area often benefit others as well. For example, optimizing JavaScript execution helps both FID and can improve LCP by freeing up the main thread.

Remember to:

  • Always test and measure before and after making changes
  • Prioritize optimizations based on impact
  • Consider both field data (RUM) and lab data
  • Create a performance budget for your site
  • Integrate performance monitoring into your development workflow

By implementing the techniques in this guide, you'll be well on your way to a faster, more user-friendly website that ranks better in search results.
